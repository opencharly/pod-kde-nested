# 2026.329.1510 — fix(check): report the surviving kwin capability on stderr, so a failure names it

## Summary

`kde-nested-kwin-no-caps` asserts `kwin_wayland` carries no file capability (so it execs under the pod's no-new-privileges). On failure it reported only to **stdout**, and the runner records a failing check's **stderr** in its reason — so the failure read `exit=1 (stderr: )` and named nothing. Measured on run `2026.327.1707`.

The failure branch now reports to stderr: the surviving capability, the file's mode/owner, and **the package that owns it** — which is what identifies who re-added the capability.

**Change class, corrected:** this is a **check/config** change (executable shell in `charly.yml`), not documentation. My first body called it documentation and concluded "no bed"; that was wrong, and the gate it skipped is supplied below.

## How tested

### Spike

RCA: a failing check's reason carries its **stderr** only, so a stdout-only report is discarded and the failure is anonymous.

Candidates, each spiked in the built image (`localhost/kde-cstream-check:check-kde-cstream-browser-2026.329.0937`):

1. **Change the runner to record stdout too** — rejected: the runner is shared org infrastructure; bending how it stores reasons to serve one check is the tail wagging the dog.
2. **Report to stderr (chosen)** — spiked by forcing the failure branch with a stubbed `getcap`, because setting a real capability needs `CAP_SETFCAP` (`unable to set CAP_SETFCAP effective capability: Operation not permitted`):

```
$ podman run --rm --network none --entrypoint /bin/sh \
    localhost/kde-cstream-check:check-kde-cstream-browser-2026.329.0937 -c '
      mkdir -p /tmp/fk
      printf "#!/bin/sh\necho /usr/bin/kwin_wayland cap_sys_nice=ep\n" > /tmp/fk/getcap
      chmod +x /tmp/fk/getcap
      PATH=/tmp/fk:$PATH
      caps=$(getcap /usr/bin/kwin_wayland 2>/dev/null)
      if [ -n "$caps" ]; then
        echo "kwin_wayland still has caps: $caps" >&2
        echo "file: $(ls -l /usr/bin/kwin_wayland 2>&1)" >&2
        echo "pkg:  $(pacman -Qo /usr/bin/kwin_wayland 2>&1 | head -1)" >&2
        exit 1
      fi
      echo PASS'

# stderr (what the runner records in the reason):
kwin_wayland still has caps: /usr/bin/kwin_wayland cap_sys_nice=ep
file: -rwxr-xr-x 1 root root 1482496 Nov 23 20:23 /usr/bin/kwin_wayland
pkg:  /usr/bin/kwin_wayland is owned by kwin 6.8.3-3

$ echo $?
1
```

That is the **exact command the diff ships** (previous revision of this body pasted `pacman -Qo` while the diff ran `pacman -Q kwin` — a different command; block 1 was right and the diff now matches). Winner: candidate 2; the RCA holds.

**Coverage (R10):** this run IS the coverage — it drives the changed branch and shows its output; the branch cannot be reached without a capability present, so the stub is the failure injection and the pasted output is what the branch emits. The pass branch is unchanged and still exercised by every run of the bed that composes this candy.
