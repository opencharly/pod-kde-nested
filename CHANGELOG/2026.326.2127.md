# 2026.326.2127 — feat: the kde-nested session as one shared candy, on the layer release that installs kdotool

## Summary

The nested-KWin session that pod-kde-vnc and pod-kde-selkies each carry a copy of, extracted into one repo so three consumers share it (R2). KWin nests **directly** in whatever compositor the composing pod provides — no sway-specific code here, no `startplasma-wayland` (which falls back to a headless KWin nobody sees when there is no systemd session).

- **`kde-nested-session`**: starts `kwin_wayland` nested in the host display (`KDE_NESTED_HOST_DISPLAY`, default `wayland-0`) on its own unnumbered socket, then `plasmashell` on that socket; carries `KDE_SESSION_VERSION=6` and the build-time `setcap -r` so KWin execs under the pod's no-new-privileges. Its plan asserts the launcher's shape at build time and, at runtime, the RUNNING service and plasmashell.
**Every file in the diff, accounted for.** `charly.yml` (the candy and the pin), `kde-nested-session` (the launcher), `.agents/skills/kde-nested/SKILL.md` (the consumer matrix: host display, socket, runtime dir, geometry, bus per pod), `AGENTS.md` (the repo's own rules and the R10 gate), `README.md` (the user overview), `.gitignore` / `.containerignore` / `.dockerignore` (the built-in build-context baseline; their header names `defaults.context_ignore`, which is charly's EMBEDDED default rather than a key in this repo's `charly.yml` — the generator writes that header, so the files are not hand-edited),. (`.github/workflows/tag-on-merge.yml` is a bootstrap-installed canonical file, not part of this diff.)

- **`require: layer-kde-shell` `v2026.325.1442` → `v2026.326.2019`** — that older tag is the WORKAROUND release (it fetched `kdotool` 0.3.0 from a pinned GitHub tarball because the `aur:` builder silently dropped the declaration).
